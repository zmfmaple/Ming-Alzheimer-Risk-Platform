# Architecture

## Components

### Web application

`frontend-react/` is the active Next.js application. Pages collect assessment data,
manage authentication, display reports, export PDFs, and show saved assessment
history. Reusable UI is under `src/components`; conversion and scoring helpers are
under `src/lib`.

### API

`backend/main.py` creates the FastAPI application. It loads model artifacts at startup
and exposes authentication, prediction, history, monitoring, privacy, and health
routes.

Supporting modules:

- `schemas.py`: request and response validation.
- `models.py`: SQLAlchemy `User` and `Assessment` tables.
- `database.py`: fixed SQLite connection at `data/runtime/alzheimers.db`.
- `auth.py`: Argon2 password hashing and JWT verification.
- `chat.py`: rule-based report explanation assistant.
- `model_config.py`: canonical deployed feature lists.

### Model artifacts

`models/` contains the fitted XGBoost classifier, numeric scaler, probability
calibrator, feature order, SHAP explainer, and training metadata. These files are
generated by `backend/train_model.py`.

### Research and reports

`reports/` contains reproducible model-evaluation outputs and the variable evidence
map. `research/hcap/` and `research/oasis2/` are supplementary analyses, separate from
the deployed questionnaire model.

## Assessment Data Flow

```text
assessment.tsx
  -> POST /predict or /predict-demo
  -> Pydantic validation
  -> training-split missing-value imputation
  -> numeric scaling
  -> XGBoost probability
  -> Platt calibration
  -> SHAP explanation
  -> optional SQLite persistence
  -> result.tsx
```

Logged-in prediction uses `/predict` and stores an `Assessment`. Guest prediction uses
`/predict-demo` and does not write to the database.

## API Groups

| Group | Routes |
|---|---|
| Service | `GET /`, `GET /health`, `GET /model/progress` |
| Authentication | `POST /auth/register`, `POST /auth/login`, `GET /auth/me`, `POST /auth/consent` |
| Prediction | `POST /predict`, `POST /predict-demo` |
| Assessments | `GET /assessments/history`, `GET/DELETE /assessments/{id}` |
| Monitoring | `GET /assessments/monitoring/data` |
| Privacy | `GET /data/export`, `DELETE /account` |
| Explanation | `POST /chat` |

`GET /model/progress` exposes non-sensitive aggregate development information for the
model dashboard: model metadata, artifact availability, model comparisons,
calibration bins, and subgroup performance. It does not expose account or assessment
records.

## Persistence

SQLite contains:

- `users`: account identity, password hash, and research-consent fields.
- `assessments`: submitted data, calibrated output, selected measurements, SHAP
  contributors, and creation time.

The database path is resolved from the repository location, so starting Uvicorn from a
different working directory no longer creates a second database.

## Active Stack

The repository contains one application stack: `frontend-react/` plus
`backend/main.py`. Superseded Streamlit and monolithic FastAPI implementations have
been removed.
